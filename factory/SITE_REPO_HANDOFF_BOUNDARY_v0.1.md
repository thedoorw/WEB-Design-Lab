# Site Repo Handoff Boundary v0.1

## Purpose

Define when work leaves WEB-Design-Lab and becomes a formal production website repository.

WEB-Design-Lab is for:
- reference study;
- reproduction cases;
- starter/template development;
- capture/comparison tooling;
- reusable layout grammar;
- production-method learning.

A formal Site Repo is for:
- one actual website identity;
- owned/approved production content;
- production assets;
- site-specific information architecture;
- deployment;
- domain configuration;
- ongoing publication.

## Handoff gate

Create / promote to a Site Repo only when all are true:

```text
SITE PURPOSE = DECIDED
PRIMARY SHELL = SELECTED
ROUTE MAP = DECIDED
CONTENT MODEL = DECIDED
ASSET RIGHTS = CLEAR
REFERENCE METHOD = PROVEN OR NOT REQUIRED
RESPONSIVE BASELINE = PASS
DEPLOYMENT TARGET = DECIDED
```

Do not create a formal Site Repo merely because a reproduction case can render.

## What moves into Site Repo

Move:
- chosen starter shell;
- site-specific HTML/CSS/JS or framework source;
- owned/approved content;
- owned/licensed media;
- site tokens;
- route map;
- deployment workflow;
- site-specific QA.

Do not move:
- unrelated benchmark cases;
- third-party reference captures;
- comparative research corpus;
- rejected experiments;
- Lab-only evidence;
- reference assets that are not licensed for production.

## Authority boundary

```text
WEB-Design-Lab
→ method / reference / reproduction / template authority

Formal Site Repo
→ production website SSOT
```

Once the formal Site Repo exists:
- production edits happen there;
- Lab may continue to improve generic factory tooling;
- Lab does not silently overwrite site-specific decisions;
- reusable improvements flow from Site Repo back to Lab only after being generalized.

## First formal Site Repo recommendation

Do not create it yet solely from Case 001.

First define:
1. actual portfolio identity/name;
2. production route map;
3. initial content set;
4. whether the target shell is the editorial starter or a later hybrid;
5. repository name and Pages/domain target.

After those five items are decided, Site Repo creation becomes a bounded implementation task.

## Case 001 result

Case 001 proves the reproduction/correction method and contributes:
- narrow editorial shell grammar;
- frozen-reference baseline method;
- automated visual-geometry comparison;
- anti-bot fallback procedure.

It does not itself define the user's final production portfolio.
