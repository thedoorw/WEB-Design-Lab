## Direction

The long-term goal is not merely to clone websites.

The goal is:

> 把網站拆成可理解、可重組、可學習的設計系統。

The fast path starts with direct reconstruction, then extracts reusable knowledge from the finished comparison.

```text
Website
→ reconstruct quickly
→ compare/correct
→ understand why the design works
→ extract reusable design rules
→ build reusable tokens/components/layout grammar
→ reuse on later sites
```

## Operating identity

The factory combines:

```text
Design Researcher
+ System Designer
+ Frontend Production Team
```

Research must not delay production. The production case itself is the primary evidence source.

## Four durable capabilities

### 1. Recover website grammar

Extract:
- layout rules;
- typography hierarchy;
- spacing rhythm;
- navigation logic;
- information density;
- image strategy;
- breakpoint/responsive behavior;
- material interactions.

### 2. Build a design-preference model

Across chosen references, track:
- information density;
- whitespace;
- typography;
- navigation;
- image ratio/treatment;
- motion intensity;
- content architecture.

### 3. Cross-site composition

Future sites may combine verified patterns from multiple references:

```text
Site A → homepage rhythm
Site B → article structure
Site C → navigation
Site D → gallery
```

The result must remain coherent rather than become a collage.

### 4. Every reconstruction increases future capability

Each case should leave behind:
- component patterns;
- layout patterns;
- responsive patterns;
- typography systems;
- navigation patterns;
- verified implementation techniques;
- failed approaches to avoid.

## Factory / Site separation

```text
WEB-Design-Lab
= methods + tools + templates + cases + QA

Formal Site Repo
= site-specific code + content + assets + deployment
```

Factory updates do not automatically mutate existing site repositories.
Sites adopt factory improvements selectively/version-by-version.
